# Examples

This page shows common `contract-check` workflows. For complete command syntax, see [CLI Reference](../commands/).

## Validate a single contract

```bash
contract-check validate contract.yaml
```

Use this for local validation during development.

______________________________________________________________________

## Generate a JSON report

```bash
contract-check validate contract.yaml --format json > report.json
```

Inspect issues:

```bash
jq '.issues' report.json
```

______________________________________________________________________

## Generate a Markdown report

```bash
contract-check validate contract.yaml --format markdown > report.md
```

Use this when attaching validation output to pull requests or documentation.

______________________________________________________________________

## Validate a contract from stdin

```bash
cat contract.yaml | contract-check validate -
```

The `-` argument tells the CLI to read from standard input.

Equivalent:

```bash
contract-check validate - < contract.yaml
```

______________________________________________________________________

## Validate generated contract content

```bash
generate-contract --table customer_events \
  | contract-check validate - --format json
```

Use stdin when the contract is generated by another tool and does not need to be written to disk.

______________________________________________________________________

## Validate multiple contracts

```bash
contract-check validate-many contracts/*.yaml
```

The shell expands `contracts/*.yaml` before `contract-check` runs.

______________________________________________________________________

## Validate recursively

```bash
contract-check validate-many --pattern "contracts/**/*.yaml"
```

Quote the pattern so the application receives it and performs app-level globbing.

______________________________________________________________________

## Stream validation results

```bash
contract-check validate-many --pattern "contracts/**/*.yaml" --format ndjson
```

Example output:

```json
{"path":"contracts/a.yaml","status":"passed","issue_count":0}
{"path":"contracts/b.yaml","status":"failed","issue_count":2}
```

Filter failed results:

```bash
contract-check validate-many --pattern "contracts/**/*.yaml" --format ndjson \
  | jq 'select(.status != "passed")'
```

______________________________________________________________________

## Separate report output from diagnostics

```bash
contract-check validate contract.yaml --format json > report.json 2> validation.log
```

This writes:

```text
stdout -> report.json
stderr -> validation.log
```

Use this in CI or scheduled jobs.

______________________________________________________________________

## Use a specific profile

```bash
contract-check validate contract.yaml --profile prod
```

Or set the profile through an environment variable:

```bash
CONTRACT_CHECK_PROFILE=prod \
contract-check validate contract.yaml
```

______________________________________________________________________

## Override output format with an environment variable

```bash
export CONTRACT_CHECK_OUTPUT_FORMAT=json
contract-check validate contract.yaml
```

A CLI option overrides the environment variable:

```bash
CONTRACT_CHECK_OUTPUT_FORMAT=markdown \
contract-check validate contract.yaml --format json
```

The final format is `json`.

______________________________________________________________________

## Run in CI

```bash
contract-check validate-many --pattern "contracts/**/*.yaml" \
  --format json \
  > validation-report.json
```

Example shell logic:

```bash
set -euo pipefail

contract-check validate-many --pattern "contracts/**/*.yaml" \
  --format json \
  > validation-report.json
```

If validation issues are found, the command exits with code `1`.

______________________________________________________________________

## Run diagnostics

```bash
contract-check doctor
```

Machine-readable diagnostics:

```bash
contract-check doctor --format json > doctor.json
```

______________________________________________________________________

## Disable color

```bash
contract-check validate contract.yaml --no-color
```

Or:

```bash
NO_COLOR=1 contract-check validate contract.yaml
```

______________________________________________________________________

## Read help

```bash
contract-check --help
contract-check validate --help
contract-check validate-many --help
```
