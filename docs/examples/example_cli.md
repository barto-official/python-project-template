# Examples

This page shows common `my-package` workflows. For complete command syntax, see [CLI Reference](../commands/validate.md).

## Validate a single contract

```bash
my-package validate contract.yaml
```

Use this for local validation during development.

______________________________________________________________________

## Generate a JSON report

```bash
my-package validate contract.yaml --format json > report.json
```

Inspect issues:

```bash
jq '.issues' report.json
```

______________________________________________________________________

## Generate a Markdown report

```bash
my-package validate contract.yaml --format markdown > report.md
```

Use this when attaching validation output to pull requests or documentation.

______________________________________________________________________

## Validate a contract from stdin

```bash
cat contract.yaml | my-package validate -
```

The `-` argument tells the CLI to read from standard input.

Equivalent:

```bash
my-package validate - < contract.yaml
```

______________________________________________________________________

## Validate generated contract content

```bash
generate-contract --table customer_events \
  | my-package validate - --format json
```

Use stdin when the contract is generated by another tool and does not need to be written to disk.

______________________________________________________________________

## Validate multiple contracts

```bash
my-package validate-many contracts/*.yaml
```

The shell expands `contracts/*.yaml` before `my-package` runs.

______________________________________________________________________

## Validate recursively

```bash
my-package validate-many --pattern "contracts/**/*.yaml"
```

Quote the pattern so the application receives it and performs app-level globbing.

______________________________________________________________________

## Stream validation results

```bash
my-package validate-many --pattern "contracts/**/*.yaml" --format ndjson
```

Example output:

```json
{"path":"contracts/a.yaml","status":"passed","issue_count":0}
{"path":"contracts/b.yaml","status":"failed","issue_count":2}
```

Filter failed results:

```bash
my-package validate-many --pattern "contracts/**/*.yaml" --format ndjson \
  | jq 'select(.status != "passed")'
```

______________________________________________________________________

## Separate report output from diagnostics

```bash
my-package validate contract.yaml --format json > report.json 2> validation.log
```

This writes:

```text
stdout -> report.json
stderr -> validation.log
```

Use this in CI or scheduled jobs.

______________________________________________________________________

## Use a specific profile

```bash
my-package validate contract.yaml --profile prod
```

Or set the profile through an environment variable:

```bash
CONTRACT_CHECK_PROFILE=prod \
my-package validate contract.yaml
```

______________________________________________________________________

## Override output format with an environment variable

```bash
export CONTRACT_CHECK_OUTPUT_FORMAT=json
my-package validate contract.yaml
```

A CLI option overrides the environment variable:

```bash
CONTRACT_CHECK_OUTPUT_FORMAT=markdown \
my-package validate contract.yaml --format json
```

The final format is `json`.

______________________________________________________________________

## Run in CI

```bash
my-package validate-many --pattern "contracts/**/*.yaml" \
  --format json \
  > validation-report.json
```

Example shell logic:

```bash
set -euo pipefail

my-package validate-many --pattern "contracts/**/*.yaml" \
  --format json \
  > validation-report.json
```

If validation issues are found, the command exits with code `1`.

______________________________________________________________________

## Run diagnostics

```bash
my-package doctor
```

Machine-readable diagnostics:

```bash
my-package doctor --format json > doctor.json
```

______________________________________________________________________

## Disable color

```bash
my-package validate contract.yaml --no-color
```

Or:

```bash
NO_COLOR=1 my-package validate contract.yaml
```

______________________________________________________________________

## Read help

```bash
my-package --help
my-package validate --help
my-package validate-many --help
```
